## 面试展开素材

简历上每一条主张，面试时都可能被追问。以下是配套说明。

### 「四层架构」——为什么是四层？

四层按**变化频率**划分：`core`（领域对象）几乎不变；`data`（SQL 与表结构）随数据库变；
`service`（业务规则）随需求变；`ui`（交互）随界面变。

**为什么 data 和 service 要分开**：合并后改一条校验规则就得动 SQL 代码，
且测试必须连数据库。分开后业务规则可脱离界面与数据库做单元测试。

### 「界面层无法访问数据库连接」——如何保证？

`Page` 及各页面的构造函数只接收 `LibraryService&`，没有获取 `QSqlDatabase` 的途径。
所以不是靠编码规范约束，而是**类型系统上的不可能**。

**验证方式**：`tests/test_library_service.cpp` 使用 `QCoreApplication`（而非
`QApplication`）即可编译运行，证明业务层确实不依赖任何 Qt Widgets 组件。

### 「Result<T>」——为什么不用异常？

1. Qt 信号槽跨越事件循环时栈已展开，与异常混用易出问题；
2. 本场景中失败是**常态**（ISBN 重复、库存不足），不属于异常情况；
3. 编译器不强制处理异常，而将失败编码进返回类型后，
   `if (!result)` 这一模式在代码审查中易于发现遗漏。

**实现要点**：内部以 `std::optional<T>` 表达成功态——相较"`bool` + `T` 成员"
的方案，它不可表达矛盾状态，且**不要求 `T` 可默认构造**、失败路径不构造 `T`。
两个私有构造函数以参数类型（`T` 与 `QString`）区分成功/失败，
对外仅暴露 `success()` / `failure()` 两个静态工厂，使调用点必须写明意图。
隐式生成的拷贝/移动构造为 public，因此可以接收和按值返回，但不能凭空构造。

### 「条件写」——如何避免并发超借？

**问题**：直觉做法是「先 `SELECT` 查库存，够则 `UPDATE` 扣减」，
但两次交互之间存在窗口期，两个事务可能都读到"还有 1 本"，导致库存减成负数。

**方案**：将判断压入 `WHERE` 子句：

```sql
UPDATE book SET available = available + :delta
WHERE id = :id AND available + :delta BETWEEN 0 AND total
```

越界时 SQL 不报错，但 `numRowsAffected()` 返回 0，据此判定操作被拒绝。
MySQL InnoDB 默认 REPEATABLE READ 下，该 UPDATE 会对目标行加排他锁，
第二个事务阻塞至第一个提交后基于最新值重新求值，因此判断准确。

**分工说明**：业务层另有一道前置检查（`findByIsbn` 后比较 `available`），
作用是给出「当前仅有 N 本可借」这类具体提示；
真正的正确性保障在数据层的条件写。两者职责不同。

### 「事务」——边界为什么在 service 层？

因为一次借阅跨越两张表（`lend_records` 与 `book`）、两个 Repository，
单个 Repository 开事务无法覆盖完整业务动作。

**事务边界 = 业务动作的边界**。借出、归还均由 `LibraryService` 开启事务，
任一步失败即回滚，避免出现"已写借阅记录但库存未扣减"的中间状态。

### 「60 个断言」——测了什么？

| 测试目标 | 断言数 | 覆盖内容 |
|---|---|---|
| `library_service_tests` | 44 | ISBN/姓名校验规则、录入与修改的业务约束、借还与归还的库存增减及边界拦截 |
| `gui_smoke_tests` | 16 | 页面构造、五个功能页的导航正确性、按钮可用状态、运行期无 Qt 告警 |

## 已知不足（主动准备）

面试中「这个项目有什么不足」几乎必问，建议主动说明：

1. **未做并发实测**。条件写的正确性由数据库行锁与当前读保证，
   但目前仅在单线程下验证，尚无两个连接并发提交的测试用例。
2. **界面测试仅为冒烟级别**。验证了页面构造与导航，
   但未模拟「填写表单 → 提交 → 校验数据库结果」的完整交互链路。
3. **无用户体系**。借阅人为字符串字段，没有登录、权限与读者表。
4. **`search` 与 `findAll` 未传递数据库错误**。二者返回 `QVector`，
   查询失败时只能返回空集合并记录日志，界面会显示"没有找到"而非"数据库故障"。
   这是返回类型选择的取舍，如需修正应改为 `Result<QVector<Book>>`。

## 可扩展方向

| 方向 | 内容 | 可延伸话题 |
|---|---|---|
| 并发测试 | 两个连接、双线程同时借同一本书，断言仅一次成功 | 事务隔离级别、行锁、`SELECT ... FOR UPDATE` |
| 操作审计 | 新增 `audit_log` 表，记录借还的操作人与变更前后值 | 触发器取舍、不可变日志表设计 |
| 服务复用 | 复用 `service` 层暴露 HTTP 接口 | 分层设计价值的验证——业务层无需改动 |
| 单元测试 | 为 `AppConfig` 的配置覆盖逻辑补测试 | 依赖注入与可测试性设计 |
